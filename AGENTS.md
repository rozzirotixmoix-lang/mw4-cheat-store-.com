# Repository conversion rules

This is the reusable MW4 master template. A setup/audit request does not authorize a game conversion. Preserve current content and behavior unless the task explicitly changes them.

## Read first

- Read [docs/architecture.md](docs/architecture.md) for source ownership, routes, commands and hosting behavior.
- Read [docs/template-defects.md](docs/template-defects.md) before treating existing behavior as correct. Defects are follow-up work, not invariants to reproduce.
- Use [docs/conversion.example.json](docs/conversion.example.json) as an intake example. It is documentation, has no runtime loader, and does not configure the site automatically. Copy it for a future conversion; obtain actual business facts before implementation.
- Reuse installed `website-template-converter`, `website-rebranding`, `technical-seo`, `website-quality-assurance`, and `deployment-readiness` skills as applicable. Discover their installed locations; do not reinstall duplicates or copy generic workflows here. These were inspected under `C:/Users/Ryzen/.codex/skills/<skill>/SKILL.md` during setup.
- Every authorized **new-site conversion** must include [docs/content-workflow.md](docs/content-workflow.md). Under `website-template-converter` and `technical-seo`, run `content:prepare` before changing the origin, plan keyword/URL ownership once, author commercial copy plus 8–12 distinct articles and 10–15 editorial forum starters when supported, finish all four locales, check/install the pack, integrate commercial copy, then build/validate. Codex writes the content; the user supplies business facts, not articles or threads. Resume drafts and validate batches instead of repeatedly planning/rephrasing. This setup and ordinary MW4 maintenance do not trigger generation.

## Project invariants

- Commercial positioning: mw4cheat.net focuses on **Modern Warfare 4 Cheats**, the primary English keyword. SEO, commercial copy, blog/forum planning, internal links and product messaging must serve relevant game-cheats search intent. Preserve the four-product architecture and verified facts. General game information belongs only where it helps explain product features, compatibility, requirements, troubleshooting or purchasing decisions; exclude unrelated gaming news, walkthroughs and entertainment topics.
- Future clones retain this commercial game-cheats positioning, using the confirmed target game's cheats keyword and accurate localized equivalents. Assign distinct supporting intents to individual URLs rather than targeting the same primary query everywhere. Connect useful editorial content naturally to the appropriate main or utility product. Apply this policy during future planning/review; a positioning clarification alone does not authorize rewriting existing content.
- Keep Astro static output, npm/package-lock.json, Tailwind 4 and shared component composition unless the requested scope changes architecture. Node must satisfy `package.json` (currently >=22.12.0).
- Identity originates in `src/config/site-url.mjs`, `site.ts`, `game.ts`, and `brand.ts`; shared styling lives in `src/styles/global.css` and `starwind.css`. The config is not a complete content rebrand: inspect all four languages, blog, forum, manifest and generated checkout copy.
- The current four product data keys are `elite`, `hwid-spoofer`, `ugc`, `skin-changer`. `elite` is an internal key, not a public `/cheats/elite/` detail page. `/products/` is the catalog; `/cheats/` is the main product. Use `src/config/catalog.ts` and `src/utils/path.ts` for enabled products and page paths.
- Product facts, features, requirements and limitations belong in `src/data/products.ts` and its locale bundles. Plan IDs/prices/durations belong in `src/data/productPricing.ts`. Update repeated prose and translations when facts change; do not silently treat prose as synchronized data. Unknown compatibility and claims remain unresolved inputs.
- Visible purchase links use `src/config/checkout.ts` helpers and internal `/go/` paths. External referral targets belong in `checkout-redirects.mjs`. Preserve `plan=monthly|lifetime` through checkout redirects; never confuse internal `elite`, checkout key `wardogs`, public `/cheats/`, and `/go/mw4-cheats/`. Additions/renames must update generators and redirect handlers together.
- Preserve unprefixed English and `/es/`, `/de/`, `/fr/`, trailing slashes on page routes, shared slugs across translations, and unprefixed `/go/` URLs. Use `useLocale`, `localizePath` and existing routing helpers. Do not create duplicate locale route trees to bypass fallback rendering.
- Keep canonical, hreflang, schema and sitemap ownership in the existing layout/config/utilities. Current privacy/terms and error/checkout routes are noindex; review indexability intentionally if scope changes it. Generated `public/robots.txt`, `_redirects`, and `go/*/index.html` must be changed through their generator.
- Preserve blog/forum slug relationships used by product related-content sections, RSS and the sitemap when rewriting content. Forum content is static; browser-local votes do not imply a community backend.
- New generated forum starters declare the publishing brand as an Organization, start with a localized editorial disclosure and have zero invented votes/comments. Existing MW4 authors/counters are unchanged. `content/policy.json` retains the original template origin during rebranding; a changed origin without `content/manifest.json` fails the build. The manifest activates approved-copy verification after a future checked pack is installed; never create it for this setup. Intermediate drafts/backups live in ignored `.content/`.
- Preserve supplied utility media under `public/images/hwid-spoofer/`, `ugc/`, and `skin-changer/`, including variants, unless replacement is explicitly requested. `scripts/part15-verify.mjs` records their hashes. Routine optimization processes gameplay only; do not broaden it to protected utility or brand assets. Brand regeneration is an intentional operation using supplied artwork.
- Keep routing behavior aligned across `src/middleware.ts` (dev), `scripts/serve.mjs` (Node), `workers/site.js` (Cloudflare), and static generation where supported. `functions/_middleware.js` is a separate Pages fallback, not the Workers entry point.

## Commands and side effects

- Inspect scripts before execution. `npm ci` installs from the lockfile. `npm run dev` serves source; `npm start` serves `dist` on port 4173 by default; `npm run preview` is Astro preview, not evidence of Worker parity.
- `npm run build` optimizes gameplay variants and rewrites tracked generated public files before building and postprocessing `dist`. Review `git diff` afterward; do not discard pre-existing changes.
- `npm run build` compiles locally and never submits URLs or deploys, even with `INDEXNOW_KEY` set. IndexNow is a separate `npm run indexnow:submit` command (validation first), requiring explicit authorization. Do not run it during ordinary checks.
- Verification order: `npm run typecheck`, `npm run build`, `npm test`, `npm run validate`, then `npm run validate:runtime` for local HTTP checks. `typecheck` uses Astro's checker (plain `tsc` cannot check Astro component imports); ignored `.content/` drafts are excluded. `npm run test:local-hosts` remains available. `node scripts/part15-verify.mjs` is the historical MW4-specific regression check, not the reusable validator. No lint script is configured.
- Validation policy lives in `src/config/validation.ts`; `src/config/protected-media.json` stores the supplied utility hashes. Astro writes `.astro/validation-config.json` from actual source data. `validate` rejects stale builds and checks output without contacting external services. See `docs/validation.md` for coverage and clone updates.
- For pre-push checks, `validate:browser` uses installed Chrome (or `QA_BROWSER_CHANNEL`) with a fresh headless profile and intercepts checkout before partner contact. `validate:cloudflare` runs pinned Wrangler strictly locally with the real asset binding and current config; its build hook rebuilds output. Both stop their temporary process trees and keep evidence under ignored `.astro/`. Neither establishes deployed account/edge behavior.
- Cloudflare deployment is `npx wrangler deploy`; its `[build]` hook invokes the ordinary build. Never use deployment as a validation command. Commit, push, deployment, DNS and indexing submissions each require task authorization; this setup authorizes none of them.

Keep this file focused on repository invariants. Put architecture details in `docs/architecture.md`, discovered defects in `docs/template-defects.md`, and reusable general methodology in the installed skills.
